# F8 `batlog ui` — design

This note covers how F8 is built. The behaviour is defined in
[F8-ui.md](../../specs/F8-ui.md).

## Libraries

Bubble Tea v2, Lip Gloss v2 and Bubbles v2 (`charm.land/bubbletea/v2`,
`charm.land/lipgloss/v2`, `charm.land/bubbles/v2`):

- They are pure Go, so `CGO_ENABLED=0` and the GoReleaser build stay as
  they are.
- They are the standard toolkit for Go terminal UIs.
- They come with a testing harness for driving key presses.

These are batlog's first dependencies beyond cobra, sqlite and plist.
`batlog ui` is the only package that imports them, so the other commands'
code does not change.

**Charts are drawn by batlog**, not by a charting library. A percent-over-
time bar chart is about 100 lines, and keeping it local lets the chart use
exactly F3's rules: sleep, data gaps, and the lowest percent per column.

## Shape: a data source, not a refactor

The plan said the loaders would move out of `cmd/`. They don't need to.
`internal/ui` defines the data it needs as an interface. `cmd/ui.go`
implements that interface with the functions `status`, `history`, `top`,
`report` and `health` already use:

```go
// internal/ui
type Source interface {
	Live(ctx context.Context) (Live, error)                // F1 + F2 from one reading, the data's age
	History(ctx context.Context, r Range) (History, error) // F3 result + samples + curve
	Apps(ctx context.Context, r Range) (Apps, error)       // F4 rows, since, notes
	AppSeries(ctx context.Context, app string, r Range) ([]Point, error)
	Session(ctx context.Context, id string) (string, error) // `top --session` text
	Report(ctx context.Context, r Range) (string, error)    // `report` text
	Health(ctx context.Context) (HealthDays, error)         // `health --trend` text + daily rows
}
```

- **Same code as the CLI:** each method calls the function its CLI command
  calls. This is what makes "same numbers as the CLI" true by
  construction, and the acceptance test checks it.
- **Text where the CLI already prints it:** Report, Session and Health
  return what `report`, `top --session` and `health --trend` print. The UI
  shows that text, styling only the `⚠` lines and the section rules.
  Battery, Apps and the sidebar need rows to select, so they get data and
  format it with `internal/textfmt`, the helpers the commands now share.
- **A warning is not a failure:** what a command would print to stderr
  comes back as a `ui.Warning` next to a usable value, shown in the key
  line.
- **Tests:** `internal/ui` tests use a fake `Source`. They need no
  database, no ioreg and no clock.
- **No import cycle:** `internal/ui` never imports `cmd`.
- **Database handle:** each `Source` call opens the database read-only for
  its own read, as each command does. A load takes 2–22 ms on a week of
  real data, so there is nothing to gain from holding a handle open.

## Packages

```
internal/ui/
  model.go     root model: range, current view, size, last data, errors; Update/View
  keys.go      key map (bubbles/key) and the help text
  sidebar.go   status, health, view list, range and data age
  battery.go   view 1: chart + session/charge list + the two detail views
  apps.go      view 2: table + app energy detail
  report.go    view 3: a viewport over Source.Report's text
  health.go    view 4: F2 lines + daily health chart
  chart.go     pct-over-time bars (lowest per column, AC/asleep/no data)
               and value bars (app energy, health)
  style.go     Lip Gloss styles; one plain set for NO_COLOR
  range.go     today/week, [ ] stepping and its bounds
cmd/ui.go      the command, the TTY check, the Source over the store
```

## Refresh

- **Timer:** a `tea.Tick` every 60 s sends a refresh message.
- **Past ranges:** samples always load up to now, so `history.Build` now
  drops sessions and charges that start after the range ends. Before, a
  past day listed later sessions too (and so would a past report).
- **Loading:** a refresh is a `tea.Cmd` that calls the `Source` for the
  current view and the sidebar in one go, then returns one `loaded`
  message.
- **Stale results:** each result carries the range it was loaded for. A
  result for a range that is no longer current is dropped, so moving
  through days with `[` quickly never shows the wrong data.
- **Selection:** each list keeps its selected row's ID. After new data
  arrives, the cursor goes back to that ID, or to the first row if the ID
  is gone.

## Tests

- **`ui.Snapshot`** runs the model without a terminal: it loads, applies
  key presses, runs every command to completion (no timer), and returns
  the screen. The tests drive it with a fake `Source` holding one fixed
  day; Bubble Tea's separate teatest module is not needed.
- **Golden screens:** every view, both details, help, yesterday and a
  scrolled list, at 80×24 and 120×40 (`go test ./internal/ui -update`
  rewrites them).
- **Layout:** every line is exactly the window's width, with and without
  colour; colour changes only escape codes, except the battery chart's
  ▓/░ shades.
- **Flows:** `[` and `]` and their limits, selection kept by ID across a
  refresh, stale range data dropped, errors shown at once or after three
  failures, details read once.
- **cmd:** `--json` and no terminal; each `Source` method's output equals
  its command's on the same fixture; a session of key presses leaves the
  database file unchanged.

## Dark wakes

A Mac asleep wakes for a moment now and then (Power Nap) and the recorder
writes a lone sample. Charted as awake, a night of sleep flickered between
░ and █. A sample with no neighbour within 90 s is now drawn as asleep, as
F3 already counts it: awake time is only the intervals of 90 s or less.
